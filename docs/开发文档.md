# TVBox-n2n 开发文档

> 本项目基于 [q215613905/TVBoxOS](https://github.com/q215613905/TVBoxOS) 与 [takagen99/Box](https://github.com/takagen99/Box) 的 GitHub Actions 自动构建仓库，
> 在其 APK 中集成了 [n2n](https://github.com/ntop/n2n) 组网客户端（edge），使 TVBox/手机等 Android 设备可以通过 n2n 组成虚拟二层局域网，实现免 root 的内网互访。

---

## 1. 项目简介与目标

- 在 TVBox 的 **设置 → 其他 → N2N 组网** 页面中提供连接/断开开关与配置项。
- 使用 Android 系统自带的 `VpnService`（无需 root）建立 L3 TUN 虚拟网卡。
- 运行跨平台编译的 n2n `edge` 进程，与 `n2n.ntop.org` 这类超级节点通信，进入指定社区。
- 通过自定义的 TUN↔TAP 桥接层把 VpnService 的“IP 包”转换成 n2n 需要的“以太网帧”，并模拟 ARP。
- 全部自动构建：GitHub Actions 每天定时拉取上游源码、打补丁、编译 n2n edge、打包发布。

---

## 2. 工作原理（架构总览）

```
                        ┌──────────────── Android 进程 ───────────────────┐
                        │                                                 │
  应用网络栈            │             ┌─────────────────────┐            │
  (TCP/UDP 数据)        │             │  VpnService 建立的   │            │
     ──────────────►    │             │  TUN 网卡 (L3 IP包)  │            │
                        │             └──────────┬──────────┘            │
                        │                      poll/read                │
                        │                        ▼                       │
                        │   ┌────────────────────────────────────────┐  │
                        │   │        tuntap_android.c 桥接线程         │  │
                        │   │  IP包 ──加14字节以太网头──► 以太网帧      │  │
                        │   │  未知目的MAC ──► 发送ARP请求并缓存        │  │
                        │   │  收到ARP请求 ──► 自动回ARP应答            │  │
                        │   │  收到ARP应答/IP帧 ──► 学习IP→MAC映射      │  │
                        │   └───────────────────┬────────────────────┘  │
                        │                       │ 环形队列(64×2112B)     │
                        │                       │        + 写管道1字节    │
                        │                       ▼                        │
                        │   ┌───────────────── pipe 读端 ──────────────┐ │
                        │   │  edge 进程（device->fd = pipe 读端）      │ │
                        │   │  读取以太网帧，经超级节点发送到对端        │ │
                        │   │  tuntap_read()/tuntap_write()            │ │
                        │   └─────────────────────────────────────────┘ │
                        └─────────────────────────────────────────────────┘
                                  ▲                        │
                          超级节点 7777/UDP          超级节点 7777/UDP
                                  │                        ▼
                        ┌────────────────────────────────────┐
                        │  n2n 社区内其它节点（edge/路由器等） │
                        └────────────────────────────────────┘
```

### 2.1 关键点一：VpnService 提供的是 TUN（L3），而 n2n edge 需要 TAP（L2）

Android 的 `VpnService` 只向应用暴露 IP 层的 TUN 设备：
- 内核 → 应用：读出来的是 **IP 包**（没有以太网头）。
- 应用 → 内核：写入的也必须是 **IP 包**。

而 n2n 的 edge 假设网卡是 TAP（二层），会发送/接收完整的**以太网帧**（14 字节头 + IP 净载）。

因此我们在 C 层做双向转换（详见第 6 节 `tuntap_android.c`）：

| 方向 | 处理 |
|---|---|
| 内核 TUN → edge | 读 IP 包 → 封装 14 字节以太网头（含 ARP 模拟）→ 入队 → 管道唤醒 edge |
| edge → 内核 TUN | 读以太网帧 → 学习/应答 ARP → 剥掉 14 字节以太网头 → 写回 TUN |

### 2.2 关键点二：edge 进程如何拿到 TUN 的文件描述符

**不能**用 `ProcessBuilder.Redirect.from(FileDescriptor)`——Android/OpenJDK 的 `ProcessBuilder.Redirect` 只有 `from/to/appendTo(File)` 重载，**没有 `FileDescriptor` 版本**，写了会直接编译失败（`FileDescriptor cannot be converted to File`）。

正确做法（与 Xray-core、AeroVPN 等一致，免 root）：

1. `int tunFd = vpnFd.getFd();` —— 取得 TUN 的 fd 号（`ParcelFileDescriptor` 仍持有所有权，关闭时统一 `vpnFd.close()`）。
2. `Os.fcntlInt(vpnFd.getFileDescriptor(), OsConstants.F_SETFD, 0);` —— `fcntl(F_SETFD, 0)` 清除 `FD_CLOEXEC`，使 `exec` 后的子进程能继承该 fd。**注意部分 ROM 的 `android.system.Os` 没有 `fcntlInt` 方法（运行时抛 `NoSuchMethodError`）**，故 `makeFdInheritable()` 做三级回退：fcntl → `ParcelFileDescriptor.dup(FileDescriptor)`（内部 dup，dup 出的 fd 不带 FD_CLOEXEC）→ 原 fd。**不要用 `ParcelFileDescriptor.fromFd()`，其参数是 `int` 不是 `FileDescriptor`（编译报 `FileDescriptor cannot be converted to int`）。**
   > 注意：Android 的 `android.system.Os.dup/close` 只有 `FileDescriptor` 版本、没有 `int` 重载，`detachFd()` 出来的裸 fd 不能直接 `Os.dup(int)`，否则 javac 报 `no suitable method found for dup(int)`。
3. 通过环境变量 `N2N_TUN_FD=<tunFd 的数字>` 告知子进程真实的 fd 号。
4. `tuntap_open()` 优先读环境变量 `N2N_TUN_FD` 并用 `atoi` 得到 fd 号，缺省回退到 `stdin(fd 0)`。
5. 停止时 `vpnFd.close()` 关闭 TUN（fd 号只是整数值，不应再对它 `Os.close(int)`）。

> 为什么不用「重定向 stdin」？因为把 fd 0 设为 TUN 需要 `Redirect.from(FileDescriptor)`，而该重载在 Android 上不存在；把 fd 号经环境变量传递是无 JNI、免 root 场景下的标准做法。

### 2.3 关键点三：为什么有环形队列 + 管道

edge 主循环用 `poll()` + `read()` 读取 `device->fd`（阻塞读）。C 桥接线程同时也在阻塞读 TUN。
直接传递同一个 fd 给 edge 会与桥接线程产生读竞争，因此桥接线程负责读 TUN，把封装好的帧放进**环形队列**，
再向**管道写端**写 1 字节唤醒 edge；edge 的 `tuntap_read()` 即 `tun_dequeue()`，先从管道读端消费信号、再出队一帧。

队列满时的策略：**覆盖最旧一帧**（实时性强于丢弃新帧，对 ARP/首包场景更友好）。

## 4. GitHub Actions 工作流（`.github/workflows/test.yml`）

### 4.1 触发方式

```yaml
on:
  schedule:                # 每天 UTC 06:59 自动构建（检查上游新提交）
    - cron: 59 6 * * *
  workflow_dispatch:       # 手动触发（Actions → Test → Run workflow）
    inputs:
      rebuild:    '忽略构建记录以重新构建'  # 勾选 true 即使无新提交也强制构建
      donotpublish: '构建后不提交发布新版'   # 勾选 true 不发布 Release
```

> 注意：**没有 `push` 触发器**。手动触发的正确方式是 Actions → 左栏 Test → Run workflow → 勾选 rebuild。

### 4.2 工作流与 Job 关系

仓库共两个工作流文件：

```
test.yml（主构建）
  触发：schedule 每天 UTC 06:59 / workflow_dispatch
  telegram-bot-api（编译 Telegram Bot API 二进制，上传成 artifact）
      │  needs
      ▼
     build（矩阵两行：TVBoxOS 与 Box）
      │  needs
      ▼
     clean（build 完成后清理 14 天前的旧 runs/artifacts）

n2n-edge.yml（edge 独立编译，单独触发）
  触发：workflow_dispatch（手动）/ push（.github/n2n/** 变更）/ workflow_call
  build（编译 edge 四 ABI：arm64/armv7/x86_64/x86，上传 n2n-edge artifact）→ 其自身 clean

  test.yml 的 build job 通过 GitHub API 下拉它产生的最新 n2n-edge 产物
```

### 4.3 `build` job 流程（核心）

| 步骤 | 说明 |
|---|---|
| Checkout (actions/checkout@v7) | 检出本仓库 |
| Check New Commit | 用 curl/jq 查上游最新 commit；与 README 记录比对，无新提交且未勾选 rebuild 则后续步骤全部跳过 |
| Checkout Source Code | `git clone` 上游仓库到 `TVBoxOSC/`，切到最新 commit |
| Extra Modify | 替换 VersionName、注入 crosswalk 备用源等（上游逻辑） |
| **集成 n2n Edge** | `python3 .github/n2n/apply.py TVBoxOSC`：合并源码/资源 + 打补丁 |
| **下载 n2n Edge 二进制** | 通过 GitHub API 拉取本仓库最新 `n2n-edge` artifact，解压到 `TVBoxOSC/app/src/main/assets/n2n/`；**找不到时跳过**（该次 APK 不含 n2n） |
| Compress Source Code | 打 `sourceCode-<commit>.tar.xz` |
| Setup Python / Install deps | 安装 pyramid 等用到的 Python 依赖 |
| Modify pyramid build.gradle / local.properties | 适配 CI 环境 |
| Release Apk Sign + Build | Run Gradle `assembleRelease`（矩阵两行分别用各仓库的构建脚本） |
| Release and Upload Assets | `ncipollo/release-action@v1` 把 `TVBoxOSC/apk/*.apk` 发布到本仓库 Release |
| Download Telegram Bot API Binary | `actions/download-artifact@v8` 拉取上游构建的 bot 二进制 |
| Post To Telegram | 若配置了 `secrets.BOT_TOKEN` 则把构建日志发到 `CHAT_ID=-1001734684817` |
| Push to master | 用 `secrets.GITHUB_TOKEN` 更新 README 中的上游 commit 记录并推回 master |

### 4.4 `n2n-edge.yml` 独立工作流（单独触发）

| 步骤 | 说明 |
|---|---|
| Checkout (actions/checkout@v7) | 检出本仓库 |
| 编译 n2n edge 二进制 | `chmod +x .github/n2n/build-edge.sh && ./.github/n2n/build-edge.sh`（详见第 6 节） |
| 上传二进制产物 | `actions/upload-artifact@v4`，name=`n2n-edge`，path=`.github/n2n/bin/*` |

触发方式：`workflow_dispatch`（Actions → Build n2n edge → Run workflow）、`push`（仅当 `.github/n2n/**` 或该工作流文件变更时自动重编）、`workflow_call`（可被其它工作流以 reusable workflow 方式调用）。每次运行后还有自身的 `clean` job 清理 14 天前旧记录。

> 为什么 edge 单独一个工作流 + 用“GitHub API 下拉 artifact”而不是在 `test.yml` 里加 `n2n-edge` job？
> `n2n-edge` 与主构建相互独立：主构建用 API 拉最新产物，此 job 未运行过时跳过即可，构建互不阻塞；
> edge 二进制是纯静态编译（静态链接 NDK 运行库），不同 commit 间无需每次重编，只有 `.github/n2n/**` 变更时才需要重编。
> 用 `download-artifact@v8` 必须声明 `needs: n2n-edge`（串行且失败会拖垮整个 build），故不使用。

## 5. Android 端源码解析

包路径：`com.github.tvbox.osc.n2n`（Java）、`com.github.tvbox.osc.ui.fragment.N2nSettingFragment`（设置页）。

### 5.1 N2nConfig.java

可序列化的配置模型，字段：

| 字段 | 默认值 | 含义 |
|---|---|---|
| `community` | `n2n` | n2n 社区名，同一社区才互通 |
| `key` | `""` | 加密密钥（可留空） |
| `supernode` | `n2n.ntop.org:7777` | 超级节点地址 `host:port` |
| `ip` | `10.0.0.2` | 本机虚拟 IP，网内须唯一（手动模式使用） |
| `autoIp` | `false` | IP 获取方式：`false`=手动指定 `ip`；`true`=自动获取（在 `ip`/`mask` 所在网段内随机选址，被超级节点 NAK 拒绝时自动换址，最多 8 次，第 4 次起连 MAC 一并更换） |
| `mask` | `255.255.255.0` | 子网掩码（同时决定自动选址的网段） |
| `mac` | `""`（空则自动生成） | edge 使用的 MAC，本地管理地址（第 2 位十六进制含 `2/6/A/E`） |
| `extraRoute` | `""` | 额外路由，如 `192.168.8.0/24`，空格/逗号分隔 |
| `mtu` | `1400` | 隧道 MTU |

- `load()/save()`：基于 Hawk（Key-Value 存储，键 `n2n_config`）。新增字段对旧配置反序列化安全（`serialVersionUID` 固定，缺失字段取默认值 `false`）。
- `randomMac()`：生成随机 MAC，强制设置本地管理位（第 2 字节 `|= 0x02`、`&= ~0x01`）。
- `prefixLengthOfMask()`：掩码 → 前缀长度（供 VpnService `addAddress`/`addRoute` 用）。
- `randomIpInSubnet(baseIp, mask)`：在 baseIp/mask 的 IPv4 子网内随机选主机地址，避开网络地址、广播地址与 `.1` 网关（自动获取 IP 用）。

### 5.2 N2nVpnService.java

继承 `android.net.VpnService`，核心流程 `startVpn(cfg)`：

> 本轮实际身份（IP/MAC）放在实例字段 `attemptIp/attemptMac`，而非直接用持久化的 `cfg.ip/cfg.mac`——自动获取 IP 与 NAK 换址时二者不同。建 TUN 到拉 edge 的完整步骤封装在 **`bringUpEdge()`**，首次连接与自动换址共用；其开头的 **`teardownEdge()`** 负责拆除上一轮 edge/TUN（各项资源允许为空）。

1. **准备二进制**：`prepareBinary()` 从 `assets/n2n/` 下按 `Build.SUPPORTED_ABIS` 选择匹配架构的二进制（`edge-arm64-v8a` / `edge-armeabi-v7a` / `edge-x86_64` / `edge-x86`），复制到 `files/n2n/edge` 并赋可执行权限。
2. **决定本轮身份**：`attemptIp = cfg.autoIp ? randomIpInSubnet(cfg.ip, cfg.mask) : cfg.ip`，`attemptMac = cfg.mac`，`attemptSeq=0`。
3. **进入前台**：`startForeground()` 在 `establish()` 之前调用，避免 API 26+ 未及时进入前台触发 ANR。
4. **建立 TUN**（bringUpEdge 内）：`Builder` 设置 MTU、虚拟 IP(`addAddress(attemptIp, prefix)`)、自身路由(`addRoute(attemptIp 所在网络地址, prefix)`) 与额外路由，`establish()` 得到 `ParcelFileDescriptor vpnFd`（即 TUN fd）。
5. **传递 TUN fd**：`vpnFd.getFd()` 取 fd 号，`makeFdInheritable()` 确保 fd 无 `FD_CLOEXEC`（`fcntlInt` 清除，部分 ROM 无此方法则回退 `ParcelFileDescriptor.dup(FileDescriptor)` dup 副本），再把 fd 号存入字段 `tunFd`。
6. **启动 edge**：`ProcessBuilder`
   - `redirectOutput(appendTo(files/n2n/edge.log))` —— edge 的 stdout/stderr 追加到日志（接在 Java 阶段诊断之后）；
   - 环境变量 `N2N_TUN_FD=<tunFd>` —— 把继承到的 TUN fd 号告知子进程（子进程内 `tuntap_open` 直接 `atoi` 使用该 fd）；
   - 命令行：`edge -c <社区> [-k <密钥>] -a <attemptIp>/<前缀> -l <超级节点> [-m <attemptMac>] -M <MTU> -d n2n0 -f -E -u 0 -g 0`（子网掩码**必须**用 `-a` 的 `10.0.0.211/24` 形式传入，**不能用 `-s`**；`-E` 开放以太网广播/组播帧——3.1.1 默认 `drop_multicast=1` 会把含 ARP 请求在内的广播帧在收发两个方向直接丢弃，而 Android TUN 三层设备的 ARP 全靠本项目 tuntap_android.c 用广播帧模拟，缺它则注册成功但 ping 不通任何对端，原因见 FAQ；`-u 0 -g 0` 用于跳过 nobody 用户默认降权，否则 `exit(1)` 秒退，原因见 FAQ；密钥/MAC 为空则不传对应参数；`-f` 前台运行、`-d` 指定网卡名仅为占位，实际由 C 层接管）。
7. **监控与自动换址**：`trackProcess()` 起线程 `waitFor()`，edge 意外退出（且仍是当前进程）则记录返回码并自动 `stopVpn(true)`；`watchEdgeLog(proc)` 另起线程每 2 秒扫描 **本 attempt 启动后新增**的 edge.log（以启动时文件长度为 baseOffset）——**不能只凭"edge 存活 N 秒"判定连接成功**：被超级节点 NAK 拒绝时 edge 不退出、每 4 秒重试一次。匹配默认日志级别标记：`[OK] edge <<<` = 已收到 REGISTER_SUPER_ACK（`sRegistered=true` → 状态显示「已连接」）；`MAC or IP address already in use` = IP/MAC 被占用；`supernode not responding` = 超级节点无响应（NAK 优先于此告警）。
   - **自动获取 IP（`cfg.autoIp`）**：同一次 attempt 累计 **2 条 NAK（约 8 秒）**即触发 `rewireAfterNak()`：`synchronized(rewireLock)` 双重校验后 `attemptSeq++`，换同网段新随机 IP，第 4 次（seq≥3）起连 MAC 一并随机，再调 `bringUpEdge()` 重建（杀旧 edge、关旧 TUN、新身份重新 establish/启动），最多 **8 次**；全部失败则 `fail()` 提示检查社区/密钥。旧 watcher 随旧进程死亡退出，trackProcess 旧线程以 `process == edgeProcess` 判定不误停。
   - **手动模式**：不换址，状态行显示「连接中（IP/MAC被占用，请更换虚拟IP）」。

**全阶段诊断**：`startVpn()` 一进入就清空并重建 `edge.log`，用 `diag()` 把设备 ABI、二进制释放、TUN 配置/建立、fd、完整启动命令、edge 退出码等逐步写入。任一早期阶段失败都通过 `fail()` 同时写日志和**静态** `sLastError`（用静态是因为服务失败即 `stopSelf`，实例字段会随 instance 清空丢失）。因此无论 edge 是否真正启动，「运行日志」都有内容、状态行也会显示「已断开（具体原因）」。

`stopVpn()`：置 `running=false` → `destroyForcibly()` 杀 edge → `vpnFd.close()` 关闭 TUN（内核自动回收虚拟网卡与路由）→ 按需 `stopForeground(true)+stopSelf()`。

`onRevoke()`：用户在系统设置撤销 VPN 授权时回调，立即断开。

### 5.3 N2nSettingFragment.java

- 继承上游的 `BaseLazyFragment`（提供 `findViewById/mContext/init/getLayoutResID` 等）。
- `init()`：绑定布局并给各设置行挂点击事件；配置行弹出输入框（`promptField` + `FIELD_*` 字段编号 + `valueOf/setField` 读写）。
- `onToggle()`：`VpnService.prepare()` 首次需弹系统授权页（`REQUEST_VPN`），授权后 `doStart()`；运行中则 `N2nVpnService.stopAll()`。
- `refreshStatus()` + `mHandler(MSG_REFRESH)`：页面可见时每 2 秒轮询一次连接状态。状态取自 `N2nVpnService.stateText()`（未连接 / 已断开（原因） / 连接中（原因） / 已连接），**「已连接」以 edge 日志出现 `[OK] edge <<<`（收到 REGISTER_SUPER_ACK）为准**；IP 展示取 `N2nVpnService.currentIp()`（本轮实际选址，自动模式下非配置值）；注册被超级节点拒绝时手动模式显示「连接中（IP/MAC被占用，请更换虚拟IP）」、自动模式显示「连接中（自动选址中(n/8)）」，连接成功后显示「已连接 IP: x.x.x.x」（绿色）；主动断开会清除失败原因，edge 意外退出则显示退出码提示。
- 「IP获取方式」行：单选「手动指定 / 自动获取」，写 `cfg.autoIp` 保存；自动模式下「虚拟IP」行显示「自动获取（连接时选择）」、连接中实时显示「自动：x.x.x.x」，点击 IP 行只提示不弹编辑框（避免误以为手动值生效）。
- 「Ping 测试」行：弹窗输入目标（默认为服务器 host，可输入虚拟网段内 IP），后台执行 `ping -c 4 -W 2`，行尾显示平均延迟摘要并弹窗展示完整输出（`summarizePing` 解析 rtt/丢包）。
- 「运行日志」行：`N2nVpnService.logTail()` 读取 `files/n2n/edge.log` 尾部 8000 字符，弹窗展示。该文件前半段是 Java 启动阶段诊断、后半段是 edge 输出——连接失败时先看这里，能区分是二进制/架构/TUN/edge 哪一环。
- MAC 行点击重新生成并立即保存。

## 6. `tuntap_android.c` 深入（TUN↔TAP 桥接）

构建时用本文件**整体替换** n2n 源码里的 `src/tuntap_linux.c`，实现 n2n 头文件声明的接口：
`tuntap_open / tuntap_read / tuntap_write / tuntap_close / tuntap_get_address`。

### 6.1 数据结构

| 符号 | 说明 |
|---|---|
| `TUN_MAX_ETH = 2112` | 帧上界。n2n 的 `N2N_PKT_BUF_SIZE` 为 2048 的 IP 包 + 14 字节以太网头 = 2062，留余量取 2112 |
| `tun_queue[64]` | 帧环形队列，满时覆盖最旧一帧 |
| `tun_pipe_r / tun_pipe_w` | 唤醒管道：桥接线程写、edge 读 |
| `arp_cache[64]` | ARP 缓存，TTL 120s，支持淘汰最旧与覆写 |
| `arp_pending_*` | 同一目标 IP 的 ARP 请求 1s 限速（避免风暴） |

### 6.2 `tuntap_open`

1. 解析 fd：读环境变量 `N2N_TUN_FD`（Java 侧传入的、由 `detachFd()+Os.dup()` 得到并可被子进程继承的 fd 号）→ `fcntl(F_GETFD)` 校验有效性 → 无效回退 `stdin(0)`。
2. 初始化队列、清空 ARP 缓存。
3. MAC：配置指定则 `str2mac`，否则 `memrnd` 随机并设置本地管理位。
4. 记录本机 IP/掩码，`tun_start_bridge()` 创建管道 + 启动桥接线程。
5. 返回值 `device->fd = tun_pipe_r`（edge 主循环对它 `poll`+`read`）。

### 6.3 桥接线程 `tun_bridge_main`

```c
poll(tun_fd, 50ms)  ──► 有数据 ──► read(tun_fd, ip, TUN_MAX_ETH)
    │
    ▼
tun_wrap_ip_packet(ip)          # 把 IP 包=>以太网帧
    │                            #  IPv4：查 ARP 缓存；
    │                            #   未知目的 MAC ──► 构造 42 字节 ARP 请求（限速）并丢弃原包
    │                            #   广播/组播 ──► ff:ff:ff:ff:ff:ff
    │                            #  IPv6：仅放行组播(首字节 0xFF)
    ▼
tun_enqueue(frame)               # 队列入队 + 往管道写 1 字节唤醒 edge
```

### 6.4 `tuntap_read` / `tuntap_write`

- `tuntap_read` = `tun_dequeue`：先读管道 1 字节信号（`EINTR` 时重试），再从队列取帧。
- `tuntap_write` 处理 edge 发回的以太网帧：
  1. **ARP 帧**（`0x0806`）：学习 `SPA→SHA`，收到针对本机的请求则**就地构造 42 字节应答**直接回内核；同时清除对应的 pending 标记。
  2. **IPv4/IPv6 帧**：仅当目的为广播/组播/本机 MAC 时才剥掉 14 字节以太网头写回 TUN；同时用帧的 IP 源地址学习 MAC。
  3. 其它帧忽略。

> 学习来源即有 ARP 应答，也有普通 IP 帧的源地址/源 MAC，覆盖了“对端直接把 IP 帧打给网关 MAC”的场景。

### 6.5 编译期收尾

我们只把 `src/tuntap_linux.c` 覆盖成 Android 版（本文件加 `#ifdef __linux__` 保护），使其在 Android/Linux 下成为唯一生效的 tuntap 实现。

其它三个 `src/tuntap_freebsd.c / tuntap_netbsd.c / tuntap_osx.c` 本身分别被 `#ifdef __FreeBSD__ / __NetBSD__ / __APPLE__` 包裹，在 Android 下编译为**空目标文件**，因此**不需要删除**，也不会产生 `tuntap_open` 重定义。

## 7. 交叉编译（`.github/n2n/build-edge.sh`）

流程（在 `ubuntu-latest` runner 上执行）：

1. 安装 `autoconf automake libtool m4 make curl`。
2. **定位 NDK**：依次查环境变量 `NDK_HOME / ANDROID_NDK_HOME / ANDROID_NDK`、`ANDROID_SDK_ROOT/ndk/*` 最新版本；都没有则用 `sdkmanager` 安装固定版 `ndk;26.1.10909125`。
3. 下载 n2n `3.1.1` 源码（`ntop/n2n` tarball）。
4. 用我们的 `tuntap_android.c` 覆盖 `src/tuntap_linux.c`（其余三个 tuntap 文件有 OS 宏保护，保留即可）。
5. `./autogen.sh`（即 `autoreconf -if`）生成 configure（含 `test -f configure` 校验）。
6. 对四个 ABI 分别 `./configure --host=... CC=...<api>=clang AR=llvm-ar RANLIB=llvm-ranlib STRIP=llvm-strip`，`make edge`，`llvm-strip` 后复制到 `.github/n2n/bin/`：
   - `aarch64-linux-android` → `edge-arm64-v8a`
   - `armv7a-linux-androideabi` → `edge-armeabi-v7a`
   - `x86_64-linux-android` → `edge-x86_64`（x86_64 模拟器）
   - `i686-linux-android` → `edge-x86`（32 位 x86 模拟器）

要点：
- `ANDROID_API=21`（minSdk），clang 交叉工具链格式 `${host}${api}-clang`。
- n2n 3.1.1 的 `configure.ac` **没有** `AC_TRY_RUN` 之类运行时探测，可选库（openssl/zstd/cap 等）默认全关，因此交叉编译安全。
- `CFLAGS=-O2`；`make edge` 依赖 `libn2n.a`（`src/edge: $(N2N_LIB)` 规则），只构建 edge 目标即可。
- 失败时打印 `configure.log` / `build.log` 尾部便于排障。

- **README 提交混入 `n2n-edge.zip`**：「下载 n2n Edge 二进制」把 zip 留在仓库根目录，`git add --all` 会带进提交。已在 Push 步骤 `git add` 前加 `rm -f n2n-edge.zip` 清理。
- **设置页看不到「N2N 组网」入口**：上游 TVBoxOS 的 `activity_setting.xml` 把设置页左侧菜单容器设为 `visibility="gone"`（上游仅一页设置内容，无需菜单），注入的菜单项无处显示。`apply.py` 已新增 `patch_setting_layout()` 将其改为 `visible`，设置页左侧显示「设置其他 / N2N 组网」竖排菜单。
- **连接后「运行日志」显示「暂无日志」/ 真机也连不上**：edge 旧打包只走 assets→filesDir，而 Android 10+(API 29) 的 W^X 限制**禁止执行应用可写目录里的二进制**，`execve` 直接失败（旧代码把错误吞了）。现已：`build-edge.sh` 额外产出 `jni/<abi>/liblegedge.so`，test 下载步骤放入 `jniLibs`，`apply.py` 强制 `extractNativeLibs="true"`，服务在 API 29+ 直接从只读可执行的 `nativeLibraryDir` 拉起 edge，低版本回退 filesDir。**改完需先重跑 Build n2n edge（产出含 jni），再跑 Test**。
- **连接即失败「VPN 接口建立异常: Bad address」（真机/模拟器均是）**：Android `VpnService.Builder.addRoute()` 硬性要求**路由目标是网络地址（主机位清零）**，源码里主机位非零直接抛 `IllegalArgumentException("Bad address")`。旧代码 `b.addRoute(10.0.0.233, 24)` 用了设备自己的主机地址，必抛。`N2nVpnService` 已加 `maskToNetwork()` 先清零主机位（10.0.0.233/24 → 10.0.0.0/24）再 addRoute，额外路由同样处理。这是此前「点连接显示未连接」的真正根因。
- **点连接后日志停在「TUN 建立成功」随即整 app 闪退**：**已定位并修复**——根因是部分 ROM 的 `android.system.Os` 类里**没有 `fcntlInt` 方法**，调用直接抛 `NoSuchMethodError`（属 `Error` 不是 `Exception`），旧代码只 `catch (Exception)`，于是穿透出去闪退且日志毫无痕迹。三层加固：① `startVpn` 后半段（fd 继承、拼命令、`ProcessBuilder`、`pb.start()`）全部改 `catch (Throwable)` 落日志后断开；② `onStartCommand` 兜底 try/catch Throwable；③ 服务 `onCreate()` 安装默认 `UncaughtExceptionHandler`，任何线程崩溃都会把**完整异常栈追加进 edge.log**（以 `!!!! 未捕获崩溃 !!!!` 开头）。fd 可继承性改为三级策略 `makeFdInheritable()`：`fcntlInt` 清 FD_CLOEXEC → 失败回退 `ParcelFileDescriptor.dup(FileDescriptor)`（POSIX 规定 dup 出的 fd 不带 FD_CLOEXEC，副本由 `stopVpn` 关闭）→ 再失败用原 fd 并在日志标注。（`ParcelFileDescriptor.fromFd` 参数是 `int` 不是 `FileDescriptor`，别用它传 FileDescriptor，编译不过。）
- `CHAT_ID` 在 `test.yml` 中硬编码为 `-1001734684817`，如需更换请同步修改。

## 11. 常见问题（FAQ）

**Q：修改代码后 Actions 不跑？**
A：工作流没有 push 触发器，需手动 Actions → Test → Run workflow（勾选 rebuild）。

**Q：为什么不用 `download-artifact@v8` 直接拉 `n2n-edge`？**
A：那会强制 `build` 等待 `n2n-edge`（`needs`），一旦编译失败整个构建中断。用 GitHub API 拉最新产物并容错跳过，更稳健。

**Q：`TUN_MAX_ETH` 为什么是 2112 而不是 2062？**
A：n2n 内部 `N2N_PKT_BUF_SIZE=2048`，加 14 字节以太网头后最大 2062；留 50 字节余量以防未来版本加填充/校验字段。

**Q：edge 进程怎么拿到 TUN fd 的？**
A：Java 侧 `vpnFd.getFd()` 取 fd 号，`Os.fcntlInt(vpnFd.getFileDescriptor(), F_SETFD, 0)` 清除 `FD_CLOEXEC` 使子进程可继承，再经环境变量 `N2N_TUN_FD=<fd号>` 告知；`tuntap_open` 读该变量 `atoi` 得到 fd 号使用，失败回退 stdin。**不要**用 `Redirect.from(vpnFd.getFileDescriptor())`（Android 无此重载，编译不过），也**不要**对 `detachFd()` 的裸 int fd 调 `Os.dup(int)`/`Os.close(int)`——Android 的 `android.system.Os` 只有 `FileDescriptor` 版本，编译会报 `no suitable method found for dup(int)`。

**Q：为什么 IPv6 只放行组播？**
A：Android VpnService 未做 ND 地址分配时，非组播 IPv6 包既无意义也可能干扰；仅碰撞 `ff00::/8` 组播足够支撑链路本地发现。

**Q：换社区/密钥后要重新授权吗？**
A：不用，配置保存在本地（Hawk），重连即可；永久撤销授权才需要重新走一次系统授权页。

**Q：`构建 n2n edge` 步骤报 `incompatible function pointer types ... event_debug/event_test/event_peer`？**
A：这是 n2n 3.1.1 源码与新 CDK Clang（16+，如 NDK 26/27）的兼容问题：Clang 16 起把 `-Wincompatible-function-pointer-types` 等诊断**默认升级为编译错误**，而 n2n 3.1.1 的 `edge_management.c`/`sn_management.c` 事件处理函数与数组声明差一个 `const`。构建脚本已在 CFLAGS 里加 `-Wno-error=incompatible-function-pointer-types -Wno-error=incompatible-pointer-types` 将其降回警告。该问题与 `tuntap_android.c` 补丁无关。

**Q：报 `src/tuntap_linux.c:345: error: conflicting types for 'tuntap_open'`，且 `n2n.h:200` 提示 previous declaration？**
A：n2n **3.1.1** 的 `tuntap_open` 是 7 参数版本（`..., int mtu)`，`metric` 参数仅在 `WIN32` 下存在；若参照 master/dev 的 8 参数签名写补丁，在 Android/Linux 下会产生 `conflicting types`。`tuntap_android.c` 必须严格按 3.1.1 的 7 参数签名实现。至于「多份 tuntap_open 冲突」的担心其实不成立：n2n 3.1.1 的 `N2N_OBJS=$(wildcard src/*.c)` 虽会打包四份 tuntap 源，但 `tuntap_freebsd/netbsd/osx.c` 分别被 `#ifdef __FreeBSD__/__NetBSD__/__APPLE__` 包成空目标文件，Android/Linux 下只有 `tuntap_linux.c` 生效，故**无需删除**其它文件。

**Q：报 `./configure: No such file or directory`（且第一个 ABI 已编译）？**
A：`Makefile.in` 的 `distclean` 规则里有 `rm -f config.log config.status configure Makefile ...`。原脚本在第二个 ABI 开始时执行 `make distclean`，此时 Makefile 已存在，于是 **`configure` 被删掉**，紧接着的 `./configure` 便报「No such file or directory」。修复：不再用 `make distclean`，只 `rm -f src/*.o libn2n.a edge` 清理内核产物，保留 `configure`。

**Q：`assembleRelease` 报 `:app:compile...ReleaseJavaWithJavac` 失败，提示 `cannot find symbol class MainActivity`？**
A：两个上游仓库都**没有 `MainActivity`**，主界面类是 `com.github.tvbox.osc.ui.activity.HomeActivity`。`N2nVpnService` 常驻通知点击后用 `Intent(this, HomeActivity.class)` 即可。注意：本地桩类若误放了 `MainActivity`，桩编译不会暴露此错，务必对齐真实类名。

**Q：Box 构建报 `ERROR: No matching distribution found for cssselect>=1.5.0 (from pyquery)`？**
A：`pyquery` 2.1.0 的元数据声明了**并不存在**的 `cssselect>=1.5.0`（cssselect 最新仅 1.2.0），Chaquopy 解析必失败。TVBoxOS 的 `pyramid/build.gradle` 已锁 `pyquery==2.0.2`，Box 未锁。工作流「Modify pyramid——build.gradle」步骤对两仓统一执行 `sed 's/install "pyquery"/install "pyquery==2.0.2"/g'`（对已锁版本幂等）。

**Q：日志止于「启动命令」，随后显示「edge 进程退出 rc=0」，edge.log 里是一大段英文用法（usage），从未真正连接？**
A：命令里传了 **`-s <掩码>`**，而 n2n **3.1.1 的 `setOption()` 没有 `case 's'`**（`getopt` 的 optstring 仍含 `s:`，能解析该参数，但 switch 落入 `default` → 返回 2 → `help(2)` 打印完整用法后**无条件 `exit(0)`**）。于是 edge 解析到 `-s` 就自杀了，返回码恰好是 0，看起来像「正常退出」。**修复**：掩码改用 `-a <IP>/<前缀>` 的 CIDR 形式传入（如 `-a 10.0.0.211/24`，`scan_address()` 会同时得到 IP 与掩码），命令行中彻底去掉 `-s`。诊断技巧：edge.log 中「启动命令」之后若紧跟 `unknown option -s` 与 usage 文本，即是此问题。

**Q：tap 设备已创建（`created local tap device ...`），但随后日志出现 `ERROR: unable to become root`、`dropping privileges to uid=...`，之后 edge 秒退（rc=1）？**
A：这是 n2n 3.1.1 的**默认降权逻辑**：`main()` 里若 `getpwnam("n2n")` 或 `getpwnam("nobody")` 命中，就把该用户的 uid/gid 设为 `ec.userid/ec.groupid`（Android 上 `nobody` 存在，uid/gid=9999）。随后：① 第 1126 行无条件 `setuid(0)` 探测 → 应用无特权，报 `unable to become root [1/Operation not permitted]`，**仅日志无害**；② 第 1329 行 `userid != 0` 命中 → `setgid(9999)`，应用进程无 `CAP_SETGID` **必然失败** → `unable to drop privileges` → **`exit(1)`**，edge 在 tap 创建成功后仍秒退。**修复**：命令行显式追加 `-u 0 -g 0`，使 `userid/groupid` 归零、整个降权分支被跳过，edge 继续以应用自身 uid 运行（Android 沙箱内本就无特权可降）。

**Q：edge 正常启动（`edge started`），但一直刷 `ERROR: authentication error, MAC or IP address already in use or not released yet by supernode`？**
A：这是**超级节点返回的 REGISTER_SUPER_NAK**（服务端拒绝，不是 App bug）。对照 3.1.1 `sn_utils.c::update_edge()`：超级节点先按 **MAC** 查登记，查不到再按 **IP** 查（命中且密钥 token 不同会把该 IP 改挂到新 MAC 后再比对 token）；simple_id 社区中**全新 MAC + 空闲 IP 必然注册成功**，NAK 只会发生在「IP 正被别的密钥的在线设备占用」或「同 MAC 登记的 token 不符」。超级节点在同一社区内按 MAC/IP 登记 edge：① 旧 edge 异常退出（崩溃/被杀）来不及发 UNREGISTER，残留登记在最后一次成功注册后 **90 秒**（`LAST_SEEN_SN_INACTIVE`）才被清理，期间同身份注册一般会被当作重连接受，token 不符才拒绝；② 更常见：**另一台设备/PC/客户端正在线占用该虚拟 IP**（在线方每 60 秒续注册，条目永不过期）。处理：a) **把「IP获取方式」改为「自动获取」**（推荐）——App 会在网段内随机选址，连续 2 条 NAK（约 8 秒）即自动换址重建，第 4 次起连 MAC 一起换，最多 8 次，全程状态行可见「自动选址中(n/8)」；b) 手动模式则自己换一个没人用的虚拟 IP；c) 把其他占用同 IP 的客户端全部断开，等约 90 秒再连；d) 自建超级节点可重启 supernode 清空登记表，或看其日志中 `created edge` 确认占用者。若 8 个随机地址全部被拒（公共社区极拥挤或节点配置了 user/password 认证），状态行会提示检查社区名/密钥。注意被 NAK 拒绝时 **edge 不会退出**、每 4 秒重试，故 App 以日志标记（`[OK] edge <<<` / `MAC or IP address already in use`）判定真实状态，不再误报「已连接」。

**Q：状态显示「已连接」（日志有 `[OK] edge <<<`），但 ping 任何对端/虚拟 IP 都不通？**
A：**n2n 3.1.1 默认丢弃广播帧**：`edge_init_conf_defaults()` 里 `conf->drop_multicast = 1`，`edge_read_from_tap()`（Tx，日志 `dropping Tx multicast`）与数据接收路径（Rx，`dropping RX multicast`）会把所有组播/广播以太网帧直接丢掉——**ARP 请求就是广播帧**。Linux/Windows 上有真实 TAP 网卡，ARP 由内核处理、不受影响；而 Android VpnService 只给三层 TUN（内核不发 ARP），本项目的 `tuntap_android.c` 必须用广播帧模拟 ARP（未知 IP 先广播 ARP 请求，收到应答后入缓存再转发 IP 包）。缺 `-E` 时双向广播皆死：本机 ping 不出去、对端也 ping 不进来，但注册（单播信令）一切正常，极具迷惑性。**修复**：命令行加 **`-E`**（`enabling ethernet multicast traffic`，即 `drop_multicast=0`）。验证：ping 对端后断开，看 edge.log 末尾 Packet stats——`TX Supernode` 计数含 `(N broadcast)` 且广播数 > 0 说明 ARP 已能发出；若 `TX Supernode: 0 pkts (0 broadcast)` 而 ping 明明发过，就是广播仍被丢弃。

**Q：主界面怎么没有 N2N 组网快捷入口？**
A：快捷入口（收藏/应用与设置图标之间的组网按钮）只在 **takagen99/Box** 主界面有该图标栏，`apply.py::patch_home_entry()` 按 `tvDrawer/tvMenu` 锚点注入，锚点缺失（q215613905/TVBoxOS 主界面无图标栏）时只打印跳过、不影响构建。两个版本都可经 **设置页左侧菜单「N2N 组网」**进入；Box 版点主界面图标会带 `n2n_go=true` 直达 N2N 子页（SettingActivity 据 extra `setCurrentItem(fragments.size()-1)`）。
